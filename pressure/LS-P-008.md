# LS-P-008 — Test fixtures assume the sibling-checkout layout

Status: VERIFIED

## Pressure

The Rust suite resolves the language checkout through sibling
paths (`../../../mncs-language`) with a `MNCS_LANGUAGE_ROOT`
override, and several tests persist checkpoints into
`tests/fixtures/.mncs/` as a side effect. Consequences observed
while running the suite from an isolated worktree:

- native-kernel integration tests fail without the override;
- `language_knowledge` unit tests fail *with* the override set
  globally, because the environment candidate shadows their temp
  fixtures (`discover` prefers `MNCS_LANGUAGE_ROOT`);
- no single invocation is green in a worktree: lib tests need the
  variable unset, integration tests need it set;
- fixture directories gain untracked `.mncs` residue on every run.

## Desired contract

Fixture workspaces live in temp dirs (never beside sources), stdlib
resolution is injected per test rather than read from ambient
process state, and one `cargo test --workspace` invocation is green
from any checkout location including worktrees.

## Workaround

Tests previously needed split invocations and post-run cleanup. This
workaround has been removed.

## Observed incident (2026-10-01)

A concurrent stdlib-extraction branch removed `library/` from the
sibling checkout mid-campaign. Every suite resolving the stdlib from
the sibling (`integration` native targets, `mcp_protocol` native
test) failed identically on `main` and on the campaign branch until
verified against the locked compiler revision instead
(`MNCS_LANGUAGE_ROOT=<cargo checkout of 21da3938>`), where all
targets pass. The self-contained capsule kernel (`ambient` unit
tests, `ambient_coherence.rs`) passed throughout: it imports no
stdlib modules. Prefer the locked revision (or vendored stdlib) over
the live sibling checkout for library-backed tests.

## Resolution (2026-10-05)

Workspace-backed service tests now use per-test temporary copies of the
immutable fixture trees. The copy omits generated `.mncs` state, and its
thread-local owner removes it when the test finishes. Service-core,
MCP, and LSP fixtures no longer select or mutate checked-in source
directories. Test processes run from a workspace child directory so
normal sibling-repository discovery works without a global
`MNCS_LANGUAGE_ROOT` override shadowing hermetic unit fixtures.

Verified with `cargo test --offline --workspace` from the selected
Language Service worktree. The full workspace suite passed, and a
post-run scan found no `tests/fixtures/**/.mncs` checkpoint residue.
