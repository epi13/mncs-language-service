# LS-P-002 — No string literals: native text queries inexpressible in MNCS

Status: CONFIRMED

## 1. Reasonable service requirement

A native (MNCS-implemented) query layer should be able to filter symbols by
name, match completion prefixes, and model LSP/JSON string fields — all
ordinary developer-tooling work over text.

## 2. Natural MNCS expression

```mncs
fn name_matches(candidate: string, prefix: string) -> (result: bool)
```

There is no such expression: the authoritative lexer produces no
string-literal token (`TokenKind` has `Identifier`, numeric literals, and
punctuation only), and the language has no string type in any source
profile through 0.16.

## 3. What prevents it

Language surface (`mncs-syntax` lexer/parser) plus standard-library
substrate: no string type, no string literals, no text operations. Byte
views (`[byte; up_to 64]`) exist for host I/O but are not general strings
and cannot be written as literals in service query sources.

## 4. Minimal reproducer

`mncs/filter_query.mncs` (this repository): bounded symbol filtering had
to be projected to integer kind-tags on the Rust side because symbol names
cannot cross into MNCS at all:

```mncs
// What the service can express: counting integer tags.
fn count_matching(tags: [i64; 8], wanted: i64) -> (matches: i64) {
    return count<8>(tags, wanted);
}
// What it cannot express: fn filter_by_prefix(names, prefix) — no strings.
```

## 5. Expected behavior

Some general string/text facility (literals, comparison, prefix matching)
sufficient for tooling queries, or an explicit language decision that
text processing stays host-side with a documented rationale.

## 6. Actual behavior

Native kernels are restricted to numeric/structural queries (status
aggregation, kind-tag counting). Every name-dependent operation
(completion filtering, workspace symbol search, rename validation) stays
in Rust permanently.

## 7. Classification

Language (`mncs-syntax` surface) with standard-library follow-on. Severity:
medium — it caps how much of the service can ever dogfood MNCS, but the
numeric kernel path is genuinely useful.

## 8. Workaround

Integer-tag projection with a documented stable mapping
(`native_filter.rs::symbol_kind_tag`, padding tag `-1`) plus differential
comparison against the Rust control. The mapping is service-owned and must
be re-validated if renumbered.

## 9. Cost of the workaround

A parallel vocabulary (tags) that must be kept in sync by tests rather
than by construction; whole query families (prefix search, fuzzy match,
JSON modeling) cannot move into MNCS at any cost.
