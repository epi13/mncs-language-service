# LS-P-002 — No string literals: native text queries inexpressible in MNCS

Status: CONFIRMED
Progress: Partially mitigated in 2026-11 by moving bounded workspace-symbol
substring selection to MNCS; Unicode lowercase and other text operations remain
host responsibilities.

## 1. Reasonable service requirement

A native (MNCS-implemented) query layer should be able to filter symbols by
name, match completion prefixes, and model LSP/JSON string fields — all
ordinary developer-tooling work over text.

## 2. Natural MNCS expression

```mncs
fn name_matches(candidate: string, prefix: string) -> (result: bool)
```

MNCS still has no general string type or string literal. The current profile
does support bounded byte views, so a service can pass host-normalized UTF-8
bytes into a native bounded operation without making those bytes MNCS strings.

## 3. What prevents it

Language surface (`mncs-syntax` lexer/parser) plus standard-library
substrate: no string type, no string literals, and no full Unicode lowercase
operation matching Rust's `String::to_lowercase()`. Bounded byte views
(`[byte; up_to N]`) can cross the service boundary and be processed by MNCS.

## 4. Minimal reproducer

`mncs/filter_query.mncs` contains both the existing kind-count kernel and a
bounded workspace-symbol substring kernel. The latter receives at most 64
already-lowercased names and a query, each at most 64 bytes, then returns a
64-slot selection mask. Rust still normalizes Unicode text and preserves
compatibility for oversized inputs or unavailable native execution:

```mncs
fn match_names(names: [[byte; up_to 64]; 64], needle: [byte; 64],
               needle_length: byte) -> (result: SymbolMatchResult) { ... }
```

## 5. Expected behavior

Some general string/text facility (literals, comparison, prefix matching)
sufficient for tooling queries, or an explicit language decision that
remaining text processing stays host-side with a documented rationale.

## 6. Actual behavior

Bounded case-insensitive workspace-symbol substring selection now executes in
MNCS for ordinary names. Unicode lowercase normalization, names over 64
bytes, empty-query enumeration, and fallback for missing Standard/backend
support remain on the host. Completion filtering and rename validation still
use host text operations.

## 7. Classification

Language (`mncs-syntax` surface) with standard-library follow-on. Severity:
medium — it caps how much of the service can dogfood MNCS, while bounded byte
operations already transfer useful query work.

## 8. Workaround

The service projects normalized UTF-8 byte views in batches, validates the
native match mask/count and artifact identities, and keeps an explicit host
compatibility path. `mncs.core.sequences.v1::count_true<64>` is reused for the
native result summary. Lowercase equivalence remains the responsibility of
the Rust boundary until an appropriate general MNCS text facility exists. The
service derives smaller input batches from the Standard scanner's documented
per-name bound, limiting each execution to 33,280 estimated scan slots.

## 9. Cost of the workaround

A bounded byte-view contract and host normalization/fallback remain to be
maintained. Prefix, fuzzy, and JSON string operations still need explicit
native text capabilities before those responsibilities can move.
