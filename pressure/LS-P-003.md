# LS-P-003 — Import-wrapped leaf diagnostics lack machine-readable provenance

Status: CONFIRMED

## 1. Reasonable service requirement

When module A fails because its import B is broken, editor diagnostics in
A should link to the exact failing span in B (LSP `relatedInformation`
with an owning URI and range), so the user jumps to the cause.

## 2. Natural MNCS expression

The compiler already preserves the causal chain:
`SourceDiagnostic.related: Vec<SourceDiagnostic>` carries the leaf
diagnostics verbatim (INGEST-P-007). The service should project each leaf
to `(uri, range)`.

## 3. What prevents it

Leaf spans are relative to the dependency's source, but nothing on the
`SourceDiagnostic` shape says so: no `source_identity`, no owning-URI
field, and no marker distinguishing leaf-relative spans from same-file
spans. The outer `MNE172` span covers the `use` module-name token, so the
service must reverse-engineer the dependency by slicing source text and
re-resolving the module name through `StoreResolver`.

## 4. Minimal reproducer

Any importing document whose dependency fails elaboration. The service
code that has to guess is `render_related` in
`crates/service-core/src/queries.rs`:

```rust
// The outer span happens to cover the `use` name token (MNE172); parse
// the module name out of source text and re-resolve it.
let dependency_uri = text
    .get(outer.span.start..outer.span.end)
    .and_then(parse_use_target)
    .and_then(|module| StoreResolver::new(store).resolve(&module) ...);
```

If a future compiler change moves the outer span or adds `related` to a
non-import diagnostic, this silently projects wrong ranges.

## 5. Expected behavior

Each `related` entry carries its owning source identity (or the compiler
guarantees `related` spans are always same-file), so projection is
mechanical, not heuristic.

## 6. Actual behavior

Heuristic recovery: URI with exact range when the dependency is resident,
URI-only when it resolves outside the store, and neither when the
`use`-target parse fails. Never a guessed same-file range (fail-closed).

## 7. Classification

Compiler/tooling contract (`mncs-compiler` diagnostic shape). Severity:
low-medium — the failure mode is degraded navigation, never wrong
navigation, by construction.

## 8. Workaround

`render_related` + `project_leaf` + `parse_use_target` as described above,
covered by cross-file behavior in the references/navigation tests. The
concrete upstream proposal: add an optional owning source identity to
`SourceDiagnostic` (or to each `related` entry), defaulting empty so all
existing constructors keep compiling through the helper.

## 9. Cost of the workaround

Brittle coupling to one diagnostic code's span convention; every new
`related` producer must be audited by hand. Estimated fix size upstream:
small (one optional field + one helper assignment), but it touches a
hot diagnostic type, so it needs its own compiler-side evidence cycle.
