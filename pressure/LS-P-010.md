# LS-P-010 — Cross-file navigation into stdlib sources

Status: OPEN

## Pressure

`use` targets now resolve against a discovered `mncs-stdlib` checkout
(`MNCS_STDLIB_ROOT`, else a `mncs-stdlib` sibling), and `use`-line
completion proposes manifest module paths. But navigation stays
snapshot-local: go-to-definition, hover detail, and references on an
imported stdlib symbol do not land in the checkout's `library/*.mncs`
source.

Concretely, `StoreResolver` hands the compiler an envelope for the
resolved source, yet the intel layer (`declaration`, `type_definition`,
symbol-by-identity) answers from the importing document's snapshot only.
An agent asking "where is `mncs.core.status.v1::Status` defined" gets no
file location.

## Why it matters for stdlib-first development

Completion tells an agent a module exists; navigation tells it what the
module means. Without definition lookup into the checkout, agents either
re-read sources through the shell (losing semantic position) or guess at
signatures.

## Options

1. Extend `declaration`/`type_definition` to resolve through
   `StoreResolver` and return locations in `file://` library URIs,
   analyzing the target on demand with the existing invalidation
   machinery (`DependencyFingerprints` already tracks cross-document
   staleness).
2. Publish a persistent symbol index from the stdlib side (Store-backed;
   see `mncs-stdlib` STDLIB-P-003) and teach the service to consult it
   before on-demand analysis.
3. Do both: (1) for correctness now, (2) for performance when indexing
   cost shows up in measurements.

## Acceptance

- Go-to-definition on `identify` in a `use mncs.demo.widget.v1;`
  consumer lands in the checkout's `library/demo/widget.mncs`.
- Hover on an imported symbol shows its declared signature and doc
  comment.
- No repeated full-checkout reparse per request (index or cache reuse).

## Related

- `mncs-stdlib` STDLIB-P-003 (Store index, reserved not built).
- `crates/service-core/tests/stdlib_discovery.rs` covers resolution and
  completion; navigation tests should extend that fixture, not invent a
  second one.
