# LS-P-007 — Candidate analysis needs file-based machine params

Status: OPEN

## Pressure

`analyze_candidate(uri, candidate_text)` is verified read-only and
machine-invokable over the resident socket and MCP surfaces. The
provider `query` transport (`tools/mnls_provider.py`) deliberately
excludes it: candidate bodies do not belong in process argv, and the
provider refuses to invent an unbounded argument channel.

As a result, Environment-mediated agents cannot reach candidate
analysis through the ambient capability path; they must speak the
socket protocol directly or use MCP.

## Desired contract

A bounded file-artifact parameter convention for candidate bodies,
provider-owned: the caller stages the candidate text at a bounded
path, passes the path plus byte bound, and the provider streams it
to the resident RPC. Same content limits as the socket surface
(`MAX_DOCUMENT_BYTES` family), same read-only guarantee.

## Why not local to the caller

The parameter transport, bounds, and cleanup belong to the provider.
Environment must not learn socket framing to work around an argv
limit, and must not pass megabyte sources on command lines.

## Workaround

Machine clients use the resident socket `analyze_candidate` RPC or
the MCP tool directly. Ambient capsule/policy flows never need
candidate bodies, so no ambient path is blocked.
