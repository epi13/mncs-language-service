# LS-P-001 — No incremental or recovery parsing; full frontend rerun per keystroke

Status: WORKAROUND

## 1. Reasonable service requirement

A language server must re-analyze after every keystroke with latency that
feels instant. After a one-character edit, only the affected regions should
be re-lexed, re-parsed, and re-elaborated; unchanged regions should reuse
prior artifacts.

## 2. Natural MNCS expression

None exists at the API level. The service calls
`ReferenceCompiler::front_end_with_resolver` on the whole document text for
every content state; there is no `reparse(previous, change)` or
`elaborate_incremental` entry point, and no stable node identities across
parses to key reuse on.

## 3. What prevents it

`mncs-syntax::parse` consumes a full `SourceEnvelope` and returns fresh
lexical/CST/AST artifacts; `mncs-compiler` elaboration has no persistent
query database or fingerprint-keyed memoization visible to consumers. The
service therefore keys reuse at whole-document granularity
(`source_identity` fingerprints in `DocumentAnalysis`).

## 4. Minimal reproducer

```rust
// One-character insertion, then re-analysis of a ~20-line file.
svc.did_change_incremental(&uri, 2, vec![insertion_of("x")]);
svc.document_diagnostics(&uri) // ~8ms: full lex + parse + elaborate
```

Measured on `valid-contracts.mncs` (debug build):
`incremental_edit_plus_reanalysis: 7.9ms`, vs `~0.1-0.4ms` for any single
query against a resident snapshot (`perf_sanity` test
`second_wave_queries_and_edit_reanalysis_stay_interactive`). The 8ms floor
is the whole-pipeline cost, not the edit-application cost (microseconds).

## 5. Expected behavior

Sub-millisecond re-analysis for small edits in small-to-medium files, with
an architectural seam (stable node IDs, fingerprint-keyed queries) toward
true incrementality.

## 6. Actual behavior

Every keystroke pays full lex + parse + elaborate + validate + obligation
generation. Absolute times are acceptable today (files are small, ~16ms
cold), but cost scales with whole-file size, not edit size, and there is no
seam to improve it without changing the compiler.

## 7. Classification

Compiler architecture (`mncs-syntax` / `mncs-compiler`). Not a language
semantic gap: the pipeline is correct, just batch-oriented.

## 8. Workaround

- Whole-document identity-bound snapshots with per-document locks and
  dependency-fingerprint staleness (`analysis.rs`, `queries.rs::snapshot`).
- Signature help deliberately avoids the AST and works from lexical tokens
  so it keeps answering mid-typing when no parse exists (`intel.rs`).
- Token-based signature help is a permanent robustness win, but it exists
  partly because no recovery/partial parse is available.

## 9. Cost of the workaround

16ms-class stalls per keystroke on tiny files; pathological on large files
(not yet measured — no large-file corpus exists). No fine-grained reuse is
possible without upstream API work. Severity grows with file size; low
today, high if MNCS files grow past hundreds of lines.
